# Pstack in Pi

## Boundary and precedence

This adapter takes precedence over every file under `upstream/`, including its Claude harness, setup workflow, persona, autonomy defaults and scripts. Follow the user's authorization and host safety rules first. This is a prompt adapter, not an extension, runner, permission system or sandbox. Do not install anything, change settings, persist policy, start recurring work, commit, push, create a PR or merge automatically. Ask before any such action. An upstream instruction to open a PR does not authorize it.

Let PACKAGE be the absolute directory containing this package.json. Let ROOT be `PACKAGE/upstream` and ADAPTER be `PACKAGE/docs/harness/pi.md`. Resolve these from the loaded entry location, never from cwd or a guessed home path. Read internal skills at `ROOT/skills/<name>/SKILL.md`, playbooks and references relative to the file that names them, and personas at `ROOT/agents/<name>.md`. Internal `/how`, `/swarm`, etc. mean read those files, not registered commands. Only `/skill:pstack` is exported. Prefer bundled files over upstream URLs. If a referenced skill belongs to another plugin, discover its actual installed location. Do not fabricate it. A missing REQUIRED step blocks completion.

## Pi tools and paths

Use the declared `read`, `bash`, `edit`, `write`, and any available search tools by their actual schemas. Map Cursor Grep/Glob to available grep/find or read-only shell searches. AskQuestion means a plain-language question unless a real question tool is declared. Keep the playbook checklist in the conversation when no checklist tool exists. Preserve every required item and mark pending, passed, blocked or optional-skipped with evidence. No invented tool calls.

Cursor skill paths map to project `.pi/skills/` or `.agents/skills/`, and user `~/.pi/agent/skills/` or `~/.agents/skills/`. These are discovery locations, not permission to copy files there. Pi package paths are resolved by the host. Do not write Cursor, Claude, AGENTS.md or home settings as a translation shortcut.

## Delegation through installed pi-subagents

Delegation requires user or applicable host authorization. If authorized and only `subagents_enable` is declared, call it with `{}` and wait for the next model request. Then inspect the actual declared `subagent` schema. Read installed help with `subagent({action:"guide",options:{topic:"tool-reference"}})` and the relevant section addresses it returns. Discover profiles with `{action:"list",options:{capabilities:true}}`, inspect candidates with `{action:"get",agent:"<discovered name>"}`, and discover exact models with `{action:"models"}` (or agent-specific models). This adapter was authored against pi-subagents 0.78.0; installed schema and guide are authoritative. Never pass unsupported fields.

The inspected schema supports direct children with top-level `agent`, `task`, `model`, `cwd`, `async`, `worktree`; use `options.context:"fresh"` and `options.timeoutMs` for bounded children. `model` is an exact `provider/id` with an optional supported thinking suffix, not a Cursor slug. Other execution controls belong inside `options`. `readonly`, `subagent_type`, `environment`, `cloud_base_branch`, `run_in_background`, `file_attachments`, Cursor `resume`, and Cursor model slugs are not dispatch fields.

Map generalPurpose or poteto-agent to an actually discovered suitable native Pi profile, not an invented profile named poteto-agent. The upstream poteto-agent persona is a file to read in the brief. Map comment-sicko likewise to a discovered profile with a report-only brief and its upstream persona path. Never create or update profiles to make a name work. `reviewer` may have edit authority; its name does not establish read-only access. Inspect capabilities. For readonly requests use a profile/tool allowlist whose declared tools exclude mutation, including destructive MCP tools. If only bash is available, restrict commands in the brief and disclose that this is an instruction, not enforced read-only isolation. Capture and compare repository status/diff before and after. This detects some changes but is not a sandbox or proof of no writes. If strict enforced read-only is required and cannot be supplied, block the step.

Use a fresh bounded child for each slice. Each task must include the user's goal, exact owned files or read-only scope, deliverable, validation/gates, stop conditions, no recursive delegation unless explicitly authorized, absolute cwd, ROOT, ADAPTER, `ROOT/skills/poteto-mode/SKILL.md`, and the selected absolute persona path. Tell the child to read ADAPTER first, then the persona and required skill leaves, preserving adapter precedence. Do not ask a child to rerun the whole parent playbook. Do not inline the whole transcript. Example brief skeleton:

> Goal: <user goal>. Investigate <bounded question> in <absolute cwd>. Do not edit files, install, persist settings, delegate, commit or perform remote actions. ROOT=<absolute path>. ADAPTER=<absolute path>. Read ADAPTER first, then <absolute persona path> and <absolute poteto-mode path>. Return cited findings, exact checks, required gates and blockers. Stop after this question is answered or report the missing prerequisite.

Use `async:true` when required for MCP-capable children, then collect the actual run through status/wait facilities and read its result reference. A launch receipt is not completion. Do not silently switch execution protocols after a launch failure. Report the failure and partial changes. Do not assume Cursor resume IDs map to Pi; default to fresh briefs with the earlier result reference. Worktree isolation is Git workspace separation, not OS/network isolation. Do not allocate worktrees or check out branches without authorization. If an authorized cloud step can be done in a local worktree, explicitly disclose the substitution and verify its branch/base through installed guide semantics; otherwise block it.

## Model selection and setup-pstack

Do not copy Cursor model slugs or Claude aliases. Select only exact provider/model IDs returned by installed model discovery and allowed by host policy. Record requested role, requested family, actual provider/id and supported thinking level before spawning. Do not infer availability from examples or repository settings. If a requested family is absent, disclose lost diversity and ask whether a same-model panel is acceptable when independent model diversity is REQUIRED. Multiple agents on one model are not multi-model verification. Optional panels may proceed with an explicit degradation note. A rejected model is not a reason to invent another ID.

`setup-pstack` is inspection and a proposed in-conversation role table only in this adapter. Discover actual models and report role mappings and budget choices. Never run its Cursor-writing steps, overwrite existing rules, or write any settings. Model policy is host-specific and session-local here. Persisting it needs a separate user-authorized design and merge that preserves unrelated settings.

## History and MCP

Use current in-context history first. For historical evidence, obtain the exact active session path from `/session` or an available host session API, and the current leaf from the host's tree/session state. Pi sessions are JSONL trees with `id` and `parentId`; never select the newest file or assume the last line is the active leaf after navigation. Trace the confirmed leaf's ancestors only. Respect compaction (`firstKeptEntryId`), branch summaries and branch-local context edits; raw messages may no longer be model-visible. Prefer a host-projected active-branch export. If active leaf or projection cannot be established, ask for an active-branch export or mark transcript-dependent work blocked. Do not search unrelated sessions, guess cwd slugs, read sibling branches as current evidence, or run upstream Cursor transcript consumers. `--no-session` has no persisted history. No transcript parser is supplied by this package.

Discover MCP through declared tools, `/mcp` or user-authorized `pi mcp list --json`. The CLI connects configured servers and may start their existing commands; it is not an offline check. For deferred tools use declared tool_search or codemode discovery (`searchTools`/`describeTool`) before calling exact tool names. Do not invent Cursor MCP names or treat configured servers as connected and authenticated. Do not add servers, authenticate, or install browsers automatically. Child MCP availability must be checked independently through capabilities and actual execution.

## Verification and explicit limits

Classify every prerequisite as REQUIRED or optional before execution. A missing required verifier, runtime, credential, independent reviewer, model diversity, browser, formal checker or MCP tool means BLOCKED/INCOMPLETE, never success or a silent skip. Record the missing prerequisite, evidence and next action. Static source checks, packaging checks and model agreement do not prove runtime behavior. Failed required checks remain failed even if optional checks pass. Optional convenience steps may be skipped with a reason when no required downstream step consumes their output.

Deferred here: Cursor Automations, bot UI and Bugbot orchestration, cloud dashboards, Bun scripts that mutate bundled script directories, Java/TLC/mise/network-dependent formal tooling, and upstream transcript consumers. Do not execute these shipped scripts as an accidental fallback. Read-only source inspection is allowed. If a playbook requires their result, stop with the corresponding incomplete gate; if optional, report `Optional skipped in Pi: <step>. <reason>.` No automatic installs, remote PR actions or persistence are supplied. The snapshot retains these files for fidelity, not as a claim they work in Pi.
